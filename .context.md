## 6. DESIGN SYSTEM & CONVENTIONS

### Colors
| Token | Value | Usage |
|-------|-------|-------|
| `--bg` | `#050505` | Page background |
| `--bg-elevated` | `#0a0a0a` | Cards, elevated surfaces |
| `--bg-hover` | `#0f0f0f` | Hover states |
| `--fg` | `#ffffff` | Primary text |
| `--grey` | `#888888` | Secondary text |
| `--grey-dim` | `#555555` | Tertiary text |
| `--border` | `#222222` | Borders, dividers |
| `--acid` | `#ffeb3b` | Primary accent (yellow) |
| `--alert` | `#ff3333` | Contact CTA (red) |

### Typography
- **Headings:** Space Grotesk (sans-serif) — weights 300, 500, 700
- **Body/Mono:** Space Mono (monospace) — weights 400, 700
- Both loaded from Google Fonts

### Naming Patterns
- Sections: `.{name}-section` (e.g., `.work-section`, `.skills-section`)
- Section headers: `.section-header` > `.section-title` + `.section-counter`
- Cards: `.{name}-card` (e.g., `.project-card`, `.pub-card`, `.activity-card`)
- Timeline items: `.timeline-item` inside `.timeline`
- Tags: `.tech-tag` inside `.tags-list`

### CSS Architecture
- Single flat CSS file, organized by numbered comment blocks (1–13)
- CSS custom properties for all design tokens
- `clamp()` used extensively for fluid typography
- CSS `order` property on `body` children for recruiter-optimized visual ordering
- No CSS preprocessor, no utility framework

### JavaScript Patterns
- Vanilla JS only, no frameworks or libraries
- All code inside single `DOMContentLoaded` listener
- IntersectionObserver for scroll animations
- Scroll listener for header state and nav highlighting
- Event delegation not used — direct listeners on elements

## 8. IMPORTANT GOTCHAS

1. **Section reordering is CSS-only** — The HTML order doesn't match what users see. The `body` has `display: flex; flex-direction: column;` and sections use CSS `order` properties. If you add new sections, you MUST assign an `order` value in CSS.

2. **Mobile nav is checkbox-based** — No JS controls the hamburger menu. It uses a hidden `<input type="checkbox" id="nav-toggle">` with CSS `~` sibling selectors. The JS only closes it on link click.

3. **`old.html` is reference only** — It's an earlier version. Don't modify it. All active work happens in `newSite/`.

4. **`tech-stack.md` is aspirational** — It describes a Go backend that does NOT exist. Don't generate Go code unless explicitly asked.

5. **No build system** — Files are served as-is. No bundler, no minifier, no npm.

6. **Missing image** — `shashi.jpeg` is referenced but not in the repo. The hero image section will show a broken image.

## 9. HOW TO WORK ON THIS PROJECT

### To preview the site locally:
```bash
cd newSite && python3 -m http.server 8000
# Then open http://localhost:8000
```

### To add a new section:
1. Add HTML in `newSite/index.html` (follow existing section patterns)
2. Add styles in `newSite/style.css` (use CSS variables, follow naming conventions)
3. Add `order: N` in CSS for the new section to control visual position
4. Add `fade-in` class to the section `<section>` tag for scroll animation
5. Add nav link in `<nav class="nav-links">` if needed
6. Update this context file

### To deploy:
- **Simplest:** Push to GitHub, enable GitHub Pages on the `newSite/` directory
- **Future:** Follow `tech-stack.md` for Go + microVM deployment
